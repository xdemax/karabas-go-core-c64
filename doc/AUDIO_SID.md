# Звук C64: тракт, захват и причина шума

Дата: 2026-11-09. Stereo SID пока не сделан; оценка ресурсов и план —
`doc/PLAN_STEREO_SID.md`.

## 1. Тракт

```text
fpga64_sid_iec (sid_top.v → sid8580.v)
        │  audio_l/audio_r, 18-bit signed
        ▼
c64_machine.v  (assign audio_l = sid_audio_l)
        │
        ▼
karabas_minig_top.v
   ├─ HDMI:  kg_hdmi_ft, 48 кГц, audio_en = ~dvi_only
   └─ DAC:   kg_pcm5102, clk_vid 27.027 МГц, DIV_BITS=2
             DAC_DAT=D14, DAC_BCK=C15, DAC_WS=C16
```

`dvi_only` задаётся прошивкой (`HW_SETUP 01 d`, по умолчанию 0). При
`dvi_only=1` HDMI-звук выключается, но PCM5102 (джек) работает.

## 2. Захват аудио

Источник — USB-граббер MS2109:

```sh
ffmpeg -hide_banner -loglevel error -f pulse \
  -i alsa_input.usb-MACROSILICON_USB_Video-02.analog-stereo \
  -t 5 -ac 2 -ar 48000 -y /tmp/opencode/c64_audio.wav

ffmpeg -hide_banner -i /tmp/opencode/c64_audio.wav \
  -af astats=metadata=1:reset=0 -f null -
```

На 2026-11-09 до фикса SID: `RMS -22 dB`, `Peak -16 dB`, `DC offset 0.079`,
`Zero crossings = 1` — то есть на выходе почти постоянный DC/шум, а не
звук. Пользователь при этом слышал «шумы», коррелирующие с работой
дисковода.

## 3. Причина: SID писался при любом I/O-обращении

`src/rtl/sid/sid_top.v`:

```verilog
input wire [1:0] cs,     // был объявлен, но НЕ использовался
...
sid8580 sid (
    ...
    .we (we),             // ← запись не гейтилась выбором SID
    ...
);
```

`fpga64_sid_iec.vhd` даёт `we => pulseWr_io` (импульс записи в **любой**
I/O) и `cs => sid_sel_r & sid_sel_l`. Без гейта запись в VIC/CIA
($D000/$DC00/$DD00) попадала в SID по младшим 5 битам адреса:

- `$D012` (raster) → SID `$12` (voice 3 control);
- `$DD00`/`$DD02` (CIA2, дисковод/IEC) → SID `$00`/`$02`;
- и т.д.

KERNAL и дисковод пишут в I/O постоянно, поэтому регистры SID непрерывно
портились — вместо музыки был шум, а при работе дисковода шум менялся.

## 4. Исправление

```verilog
.we (we & (|cs)),
```

Теперь SID пишется только когда `cs_sid=1` (реально выбраны $D400-$D7FF).

## 5. Как проверить

1. Собрать и залить `c64.kg`.
2. Сбросить C64 (`F12`) и ввести короткую программу (прямые адреса, без
   `+` — через serial `+` иногда приходит не тем символом):

```basic
10 poke54296,15
20 poke54273,100
30 poke54278,240
40 poke54276,33
run
```

3. Записать 5 секунд с MS2109 и посмотреть `astats`: должен появиться
   переменный сигнал (RMS/Peak, zero crossings >> 1), а не DC.
4. Затем проверить музыку в демо/игре.

## 6. Результаты после гейта `cs`

После сборки с `.we(we & (|cs))` пользователь запустил демо —
**SID поёт**. Это подтверждает, что основная причина была именно в
отсутствующем гейте `cs`: до фикса любая запись в I/O (VIC/CIA, дисковод)
попадала в регистры SID.

- тон **появился**: Goertzel по записанному WAV даёт чёткий пик
  **1480–1500 Гц** (амплитуда 7.2 против 0.1–0.3 на остальных частотах);
- в записи остаётся большой **DC offset** (0.35), SID-сигнал
  однополярный/смещённый; HDMI/DAC получают его напрямую, без
  DC-blocker, который есть в MiSTer `audio_out`;
- поэтому добавлен DC-blocker в `c64_machine.v`:

```verilog
aud_dc_l <= aud_dc_l + ((aud_a_l - aud_dc_l) >>> 18);
aud_ac_l <= aud_a_l[17:0] - aud_dc_l[17:0];
```

`shift 18` при 31.25 МГц — это ~8.4 мс / ~19 Гц high-pass: постоянка и
низкочастотный гул уходят, тон 1.5 кГц и музыка проходят.

После сборки с DC-blocker (`c64.kg` md5 `a3f8e37d…`) тон остался
(Goertzel 6.8 на 1480–1500 Гц). Оставшийся в WAV `DC offset = 0.35` — это
смещение **входа граббера MS2109**, а не SID: судить по `Zero crossings`
без учёта DC нельзя, надёжнее Goertzel/спектр.

Артефакты:

- `src/c64.kg` — md5 `a3f8e37d19bd3dcd4f79f47b3176e0fa` (с DC-blocker,
  текущий);
- `doc/artifacts/c64_sid_working_882e0e65.kg` — md5 `882e0e65…`
  (рабочий без DC-blocker, на случай отката).

## 7. Примечания

- `sid_ver=2'b00` (6581), но `sid_top.v` — обёртка вокруг **8580**; это
  осознанно (порт из UnoXT), на тембр влияет, но не на факт звука.
- `sid_filter=2'b11`, фильтр включён.
- Если после гейта звук всё ещё слабый/шумный — следующий шаг: проверить
  формат `audio_data` (signed/excess) и фильтр `sid_filters.v`.
- Захват идёт с USB-граббера (MS2109), а не с джека напрямую; для проверки
  джека нужен кабель в линейный вход граббера.
