# Память Karabas Go / Mini / Mini G — для портирования ядер

Дата: 2026-11-08. Документ общий для всех ядер Karabas. Проверено на C64
(`karabas-go-core-c64`) и UKNC (`karabas-go-core-uknc`, `uknc_framebuffer.v`).

## 1. Что стоит на плате

| Память | Объём | Организация | Примечание |
|---|---|---|---|
| SRAM | **4 МБ** | 2 × `IS61WV20488BLL-10TLI`, по 2M × 8 = 2 МБ каждая | две микросхемы работают как одна 2M × 16 |
| SDRAM | **32 МБ** | 16-битная, `SDR_A[12:0]`, `SDR_BA[1:0]`, `SDR_DQ[15:0]`, `SDR_DQM[1:0]` | в C64-ядре пока не используется |
| BRAM FPGA | ~936 Кбит (XC6SLX25) | 52 × RAMB16 + RAMB8 | ROM-ы, цветовая RAM, таблицы, FIFO, OSD, строчные буферы |

Платы Go / Mini / Mini G используют одинаковые SRAM/SDRAM; отличаются видео
(Go — VGA/FT812, Mini/Mini G — HDMI/zhdmi) и тактированием, но память одна и та же.

## 2. SRAM: сигналы и организация

В top-модуле:

```verilog
output wire [20:0] MA;      // 21 бит адреса = 2M слов
inout  wire [15:0] MD;      // 16 бит данных
output wire [1:0]  MWR_N;   // запись, активный низкий: [0] младший байт, [1] старший
output wire [1:0]  MRD_N;   // чтение, активный низкий: [0] младший байт, [1] старший
```

Логически:

```
MA[20:0]  -> 2M адресов
MD[15:0]  -> 16 бит
2M × 16   = 4 МБ
```

Две микросхемы — это **байтовые половины**, а не два независимых банка:

- `MWR_N[0]` / `MRD_N[0]` — `MD[7:0]` (младший байт);
- `MWR_N[1]` / `MRD_N[1]` — `MD[15:8]` (старший байт);
- для 8-битной записи: `MWR_N = 2'b10` (или `2'b01` для старшего байта);
- для 16-битной записи: `MWR_N = 2'b00`;
- для чтения обоих байт: `MRD_N = 2'b00`.

Это подтверждается UKNC-фреймбуфером: он пишет 16-битные слова, опуская оба
`WE_N` одновременно. Если бы это были два банка, такая запись была бы неверной.

**Важно:** не считать, что «2 чипа по 2 МБ» — это два банка по 2 МБ 16-битных
слов. Это два 8-битных чипа, вместе дающие 2M × 16 = 4 МБ. Адрес 21 бит,
данные 16 бит.

## 3. Тайминги

`IS61WV20488BLL-10TLI` — асинхронная SRAM, `tAA` = **10 нс**. С учётом задержек
выводов FPGA (pad out + tAA + pad in) реально нужно около **21 нс** от адреса
до устойчивых данных на входе FPGA.

Практические варианты:

### Вариант A — частота ≤ 32 МГц (например, C64 31.25 МГц)

Один доступ = один полный такт:

- phase 0: выставить адрес (и данные/`WE` для записи);
- phase 1: держать адрес/данные, снять `WE`, для чтения оставить `OE`;
- следующий phase 0: сэмплировать `MD`.

Адрес стабилен ~32 нс — с запасом. Запись: импульс `WE` ~16 нс, адрес/данные
держатся до следующего phase 0.

### Вариант B — частота 50 МГц (20 нс)

Одного такта мало для чтения (20 нс < 21 нс). Используйте:

- два такта на чтение (40 нс), адрес держится;
- `ODDR2` для `WE`, чтобы получить короткий импульс между фронтами;
- `(* IOB = "TRUE" *) reg [15:0] din;` для входных данных — это уменьшает
  pad-to-FF задержку.

Именно так сделано в `uknc_framebuffer.v` (UKNC): запись за два такта,
чтение за два такта, `WE` через `ODDR2`, данные в IOB-регистре.

### Вариант C — 16-битные слова

Если ядру нужны 16-битные слова (видео, кадровый буфер), используйте
`MWR_N = 2'b00` / `MRD_N = 2'b00` и работайте со всем `MD[15:0]`.

## 4. Арбитраж

SRAM одна на всё ядро: CPU/машина, видео-кадры, образы дисков. Нужен арбитр.
Проверенная схема в C64 (`c64_memory.v`):

- C64/картридж имеет приоритет;
- если C64 не обращается, обслуживается вспомогательный порт (D64/видео);
- запросы вспомогательного порта **держатся до `ack`** (`vr_req`/`vr_ack`,
  `d_rd`/`d_ack`), иначе при занятом C64 запрос теряется;
- каждый доступ занимает целый `clk_sys` и обе фазы `clk_sram` (2×`clk_sys`);
- приоритет вспомогательного порта: видео-запись → D64 → видео-чтение
  (или свой порядок под нагрузку);
- один вход `c_ce`/`c_we` для машины, один `d_*` для диска, `vw_*`/`vr_*` для видео.

Если видео-поток большой, ставьте строчный буфер в BRAM и читайте SRAM
пачками, как в UKNC/C64, а не по пикселю.

## 5. Карта памяти (пример C64)

Адреса — **словные** (2M слов). В областях машины/картриджа/D64 используется
младший байт; видео — полные 16-битные слова.

| Словный адрес | Размер | Что |
|---|---|---|
| `0x000000–0x00FFFF` | 64 КБ | C64 RAM |
| `0x010000–0x01FFFF` | 64 КБ | RAM картриджа |
| `0x020000–0x11FFFF` | 1 МБ | ROM картриджа |
| `0x120000–0x15FFFF` | 256 КБ | образ D64 |
| `0x160000–0x19FFFF` | 256 КБ | кадр A |
| `0x1A0000–0x1DFFFF` | 256 КБ | кадр B |
| `0x1E0000–0x1FFFFF` | 128 КБ | свободно |

> **Обновление 2026-11-09:** в C64 ядре видео больше не использует SRAM.
> `c64video.v` держит 4 строки по 504 пикселя в BRAM (2 RAMB16), а области
> кадров `0x160000–0x1DFFFF` освобождены и могут быть отданы под другие нужды.
>
> **Обновление 2026-11-11:** CRT-банки пишутся в `0x020000…` (словные
> адреса); PRG пишется в C64 RAM через `p_*`; F-транспорт CRT использует
> секторный буфер 512 Б. Подробности — `doc/STATUS_2026-11-11.md`.

Для нового ядра достаточно выбрать свою карту в этих 2M слов; адрес 21 бит.

## 6. Ограничения UCF

Для SRAM нужно задать тайминги. Пример из C64 (`karabas_minig.ucf`):

```tcl
TIMEGRP "TG_SRAM_IN" = PADS("MD<*>");
TIMEGRP "TG_SRAM_OUT" = "TG_SRAM_IN" PADS("MA<*>") PADS("MRD_N<*>") PADS("MWR_N<*>");
TIMESPEC "TS_SRAM_OUT" = FROM FFS TO "TG_SRAM_OUT" 8 ns DATAPATHONLY;
TIMESPEC "TS_SRAM_IN"  = FROM "TG_SRAM_IN" TO FFS 20 ns DATAPATHONLY;
```

- `TS_SRAM_OUT` — от регистров FPGA до адреса/`WE`/`OE`; 8 нс.
- `TS_SRAM_IN` — от `MD` до входных регистров. В C64 стоит 20 нс (без IOB),
  в UKNC — 4 нс, потому что там данные защёлкиваются в IOB-регистре.
- Если используете IOB-регистр, уменьшайте `TS_SRAM_IN` и проверяйте, что
  XST действительно поставил регистр в IOB.

## 7. Чек-лист для нового ядра

1. Определить карту в словных адресах (21 бит, до 2M слов).
2. Решить, где 8-битные байты, а где 16-битные слова.
3. Выбрать тайминг: ≤32 МГц — полный такт; 50 МГц — два такта + `ODDR2`/IOB.
4. Сделать арбитр с приоритетом и `ack` для медленных портов.
5. Добавить `TIMEGRP`/`TIMESPEC` для `MD`, `MA`, `MRD_N`, `MWR_N`.
6. Проверить простым тестом: записать байт, прочитать, сравнить; затем
   16-битное слово; затем работу под нагрузкой (видео + машина).
7. Не забыть, что обе микросхемы — байтовые половины, а не банки.

## 8. Референсные реализации

- `karabas-go-core-uknc/src/rtl/uknc_framebuffer.v` — SRAM-фреймбуфер:
  `ODDR2` для `WE`, чтение за два такта, IOB-регистр, арбитраж с записью.
- `karabas-go-core-c64/src/rtl/c64_memory.v` — универсальный контроллер:
  C64/картридж + D64 + видео, байтовые разрешения, `ack`-рукопожатия,
  карта из раздела 5.
- `karabas-go-core-c64/src/rtl/c64video.v` — видео-конвертер C64:
  4 строки BRAM, genlock по кадру, 720×576@50. Внешнюю SRAM не использует.
- `karabas-go-core-c64-unoxt-test/src/rtl/c64_machine_unoxt.v` — пример,
  где 64 КБ RAM вынесены в BRAM (`gen_ram`), а SRAM используется только
  под кадры.

## 9. SDRAM (если понадобится)

32 МБ, 16-битная, стандартные `SDR_A[12:0]`, `SDR_BA[1:0]`, `SDR_DQ[15:0]`,
`SDR_DQM[1:0]`, `SDR_WE_N`, `SDR_CAS_N`, `SDR_RAS_N`, `SDR_CLK`.
В C64-ядре не используется, но пригодится для REU/GeoRAM/больших картриджей.
Для неё нужен отдельный контроллер с инициализацией, refresh и арбитражем;
не путать с асинхронной SRAM.
