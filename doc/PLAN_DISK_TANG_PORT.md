# План: перенос дисковода Tang C64Nano в Karabas C64

Дата: 2026-11-10

## Цель

Довести дисковод Karabas C64 до уровня Tang C64Nano: поддержка G64, запись
треков и сохранение, при сохранении текущей интеграции с `img_sdc`, SRAM и
оверлеем 1541 ROM. MiSTer-вариант не портируем: ему нужны DDR3 и ARM/HPS.

## Что есть сейчас

Наш дисковод — это UnoXT/Dar:

- `src/rtl/iec/c1541_sd.vhd` (285 строк) — обвязка 1541 + GCR + загрузка D64
  через `dsk_addr`/`dsk_data_in`;
- `src/rtl/iec/c1541_gcr.v` (244) — D64 → GCR, без G64;
- `src/rtl/iec/c1541_logic.v` (243) + `c1541_via6522.vhd` — 1541 CPU/VIA;
- `src/rtl/c64_d64_loader.v` — загрузка D64 с SD в SRAM `0x120000`;
- `src/rtl/c64_d64_rd.v` — побайтовое чтение D64 из SRAM для `dsk_*`;
- `c64_machine.v`: `dsk_wr`/`dsk_data_out` **не подключены**, запись с C64
  никуда не сохраняется;
- ROM 1541: stock + оверлей 8/16 КБ (`c64_rom_loader`, слот 3).

Итог: обычные D64 читаются, G64 нет, записи нет.

## Сравнение

## Что берём из Tang

Файлы-источники (C64Nano-2.9.13):

- `src/c1541/c1541_sd.vhd` — загрузка образа, raw/G64, save FSM;
- `src/c1541/gcr_floppy.vhd` — GCR + raw G64 + запись;
- `src/c1541/c1541_logic.vhd`, `via6522.vhd` — 1541;
- `src/c1541/mist_sd_card.sv` — интерфейс SD (нам нужно заменить).

У нас уже есть почти та же 1541-логика (`c1541_logic.v` + `c1541_via6522.vhd`)
и 8 КБ track buffer, поэтому в первую очередь переносим `gcr_floppy` и
`c1541_sd`-обвязку, а не весь блок целиком.

## Этапы

### 1. G64/raw + запись в GCR-модуле

- Взять `gcr_floppy.vhd` из Tang как основу (или портировать его изменения в
  наш `c1541_gcr.v`).
- Добавить сигналы:
  - `raw`, `raw_track_len`, `disk_g64`, `max_track`, `disk_freq`;
  - `save_track`, `track_modified`, `save_track_stage`.
- Проверить, что D64-путь остаётся прежним: D64 → GCR по секторам.
- Для G64: raw-байты трека читаются из буфера, `raw_track_len` задаёт длину;
  запись возвращает изменённый трек в буфер.
- Тест: обычный D64, затем G64 с защитой.

### 2. Адаптер образа: `img_sdc` → track buffer

Tang использует `mist_sd_card` (`sd_lba`, `sd_buff_*`). У нас образ уже
загружается через `img_sdc`/`c64_d64_loader` в SRAM.

Вариант A (минимальный):

- Оставить `c64_d64_loader` + SRAM-образ.
- Написать адаптер, который по запросу `sd_lba`/`sd_buff` отдаёт 512-байтовый
  сектор из SRAM (адрес `0x120000 + lba*512`), с `sdc_rd`/`sdc_done`.
- Для D64: 256-байтовые сектора упакованы в 512-байтовые блоки, как сейчас.
- Для G64: нужен формат/таблица треков; либо отдельный загрузчик G64 в SRAM,
  либо разбор G64 на этапе загрузки в `c64_d64_loader`.

Вариант B (ближе к Tang):

- 512-байтовый кэш сектора + track loader в `c1541_sd`;
- образ читается по секторам из `img_sdc` по требованию (медленнее, но без
  предзагрузки всего образа).

Рекомендация: A для первого этапа, B — если понадобится G64/большие образы.

### 3. Запись и сохранение

- Подключить `dsk_wr`/`dsk_data_out` от `c1541_sd` к SRAM-образу.
- Добавить write-порт в `c64_memory` (по аналогии с `d_rd`, но `d_wr`) или
  отдельный порт для записи D64-образа.
- `save_track`/`track_modified` из `c1541_sd` должны обновлять образ в SRAM.
- Сохранение на SD:
  - если прошивка/`img_sdc` умеет писать сектора в файл — добавить
    `sdc_wr`/`sdc_sector` и запись изменённых секторов;
  - если нет — сохранять только в SRAM на время сессии и явно указать это в
    README/OSD.
- Write-protect: `disk_readonly` + переключатель в OSD.

### 4. ROM и DolphinDOS

- Наш ROM-оверлей 1541 уже есть; проверить 8/16 КБ и stock fallback.
- Для DolphinDOS нужен внешний ROM и parallel bus; на Mini G параллельный
  порт не выведен, поэтому этот пункт — только если появится аппаратная
  возможность. В Tang он уже реализован, но для нас не обязателен.

### 5. Ресурсы и тайминг

- Tang: `c1541_sd` 358 + `gcr_floppy` 457 строк; у нас 285 + 244.
- Track buffer 8 КБ уже есть (4 × RAMB16); сейчас занято 46/52 RAMB16,
  83–84% slices, 59% LUT.
- Ожидаемая добавка: ~200–400 LUT, без новых больших BRAM.
- После каждого этапа: `make minig FAST=1`, проверить `Timing Score`,
  slices, RAMB16; при нехватке — оптимизировать/урезать (DolphinDOS, raw G64).
- Не трогать карту памяти: D64 `0x120000`, video `0x160000`.

### 6. Проверка

1. Загрузка обычного D64, LOAD"$", LOAD"*", RUN.
2. Сборка/чтение каталога, смена диска, eject → stock.
3. G64-игра с защитой.
4. Запись (SAVE) и повторное чтение; сохранение после reset/eject.
5. 1541 ROM overlay (stock/override) и JiffyDOS.
6. Сброс/загрузка ROM во время работы диска.
7. Timing/resource, отсутствие пересечений SRAM.

## Порядок работ

1. `gcr_floppy` G64/raw + запись (локально, без смены образа).
2. `c1541_sd` save/track FSM и адаптер `dsk_*`.
3. SRAM write-port + сохранение (сессия).
4. SD write-back (если поддержит прошивка).
5. DolphinDOS/parallel (опционально).

## Риски

- `mist_sd_card` не совпадает с `img_sdc`; нужен адаптер секторов.
- G64 в SRAM: образ и таблица треков должны помещаться в 256 КБ D64-региона
  или в отдельный регион; проверить карту.
- Write-back на SD может быть недоступен без доработки прошивки.
- VHDL-2008 конструкции Tang в ISE 14.7: при переносе заменить на VHDL-93,
  если XST ругается.
- Ресурсы: slices уже 84%; G64/write могут не влезть без оптимизации.
