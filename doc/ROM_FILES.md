# ROM-файлы C64 и 1541 (OSD)

Дата: 2026-11-09 (обновлено 2026-11-11). Реализовано через образы SD
(`img_sdc`, тип OSD `F`), как дискеты в Amiga. Заводские ROM всегда остаются
в ядре. Текущее состояние PRG/CRT — `doc/STATUS_2026-11-11.md`.

## 1. Файлы на SD

Каталог: `/c64/roms`

| Файл | Размер | Назначение |
|---|---:|---|
| `JiffyDOS_C64.bin` | 8 КБ | KERNAL C64 (JiffyDOS или custom) |
| `c64.rom` / любой 16 КБ | 16 КБ | BASIC + KERNAL одним файлом |
| `JiffyDOS_1541.bin` | 8 КБ | верхняя половина ROM 1541 (Jiffy-патч), низ — stock |
| `JiffyDOS_1541-II.bin` | 16 КБ | полный ROM 1541 (JiffyDOS) |

Файлы **не встроены** в ядро: их кладёт пользователь. Если файла нет, слот
пуст, нажат `Eject` или размер не совпал — работают **заводские** ROM,
зашитые в BRAM (`rom_c64_kernal`, `rom_c64_basic`, `sprom_c1541`).

## 2. OSD

- **page 0**: Reset, Drives, System, About.
- **page 1 About**: авторы.
- **page 2 Drives**: Disk 8, PRG (`FL`, slot 1), CRT (`F`, slot 5),
  1541 ROM (`F`, slot 3).
- **page 3 System**: C64 KERNAL (`F`, slot 2), Joystick swap.

```json
{"type":"F", "name":"C64 KERNAL", "slot":2, "extensions":".rom,.bin",
 "dir":"/c64/roms", "page":3},
{"type":"F", "name":"1541 ROM", "slot":3, "extensions":".rom,.bin",
 "dir":"/c64/roms", "page":2}
```

- **slot 2**: 8192 байта → KERNAL (пишется по смещению `0x2000` в 16 КБ
  карте ROM); 16384 байта → BASIC+KERNAL.
- **slot 3**: 16384 байта → полный ROM 1541; 8192 байта → верхняя половина
  (`0x2000..0x3FFF`), нижняя (`0x0000..0x1FFF`) остаётся заводской. Так
  работают 8-КБ JiffyDOS-патчи (например, `JiffyDOS_1541.bin` — это ровно
  вторая половина 16-КБ `JiffyDOS_1541-II.bin`).
- **Eject**: `Del` в файловом браузере (как у Amiga). Если ничего не выбрано,
  в OSD показывается `default`, а ядро использует заводской ROM.
- `filename`/`autoload` для `F` не нужны: прошивка монтирует выбранный файл
  в слот и запоминает его. **На практике `autoload: true` у F не
  срабатывает при старте ядра**; у `FL` autoload работает (см.
  `doc/STATUS_2026-11-11.md`).
- **PRG** — отдельный `FL`-пункт (slot 1), не `img_sdc`: `FILELOAD` +
  `c64_prg_loader.v`, затем авто `RUN`.
- **CRT** — `F`-пункт (slot 5), как ROM: `img_sdc` → секторный буфер →
  MiSTer-парсер CRT → SRAM-банки → `cartridge.v`. Текущие ограничения —
  в `doc/STATUS_2026-11-11.md`.

## 3. Диск и ROM — разные слоты

`img_sdc` поддерживает до 8 образов; `IMG_MOUNTED` — маска:

| Слот | Что |
|---:|---|
| 0 | Disk 8 (`.d64`) |
| 1 | PRG (`FL`, не `img_sdc`) |
| 2 | C64 KERNAL/BASIC |
| 3 | 1541 ROM |
| 5 | CRT (`.crt`, `F`, загрузка в SRAM) |

Монтирование ROM **не снимает дискету**: это отдельный слот и отдельная
память. ROM пишется в BRAM-overlay, D64 — в SRAM по `0x120000`. Оба образа
остаются доступными:

1. монтируешь KERNAL (slot 2) → ядро читает его в overlay;
2. монтируешь Disk 8 (slot 0) → D64 заливается в SRAM;
3. `Eject` ROM → снова stock, диск не трогается;
4. `Eject` Disk 8 → дискета снята, overlay ROM не трогается.

`img_sdc` обслуживает один запрос за раз, младший слот имеет приоритет:
диск (slot 0) всегда обслуживается раньше ROM (slot 2/3), а после чтения
данные остаются в своей памяти.

## 4. Как это работает

- **Заводские ROM остаются в ядре константами.** Это гарантирует
  stock-загрузку даже без SD-файлов.
- Для файлов есть отдельные **overlay RAM**: `c64_rom_ov.v` (8 КБ × 2 для
  C64, 16 КБ для 1541). Запись — с `clk_host`, чтение — с `clk_sys`/`clk32`.
- `c64_img_mount.v` превращает импульс/уровень `img_sdc` в постоянные
  `mounted`/`size` для слотов 0/2/3, чтобы монтирование ROM не меняло размер
  диска и наоборот.
- `c64_rom_loader.v` читает сектора `img_sdc` (slot 2/3) и пишет overlay,
  выставляя `kernal_loaded`/`basic_loaded`/`c1541_loaded` **только после
  полной валидной загрузки** (8/16 КБ). Пока флаг 0 — читается заводской
  ROM; флаг 1 — overlay.
- После загрузки/снятия ROM формируется reset C64/1541 ~67 мс, чтобы новый
  ROM вступил в силу **автоматически**, без ручной перезагрузки. Детектор
  спада `rom_busy` исправлен (раньше сравнивались уже сдвинутые сигналы и
  спад терялся). Reset **не сбрасывает** tracker и overlay: выбранный ROM
  переживает OSD Reset и кнопку; только power-on очищает монтирование.
- OSD Reset (`softsw[0]`) теперь обрабатывается по фронту и не держит C64 в
  reset, пока пункт меню остаётся выбранным.

## 5. JiffyDOS

JiffyDOS — это два ROM: KERNAL C64 и ROM 1541. Быстрый протокол включается,
когда обе стороны его понимают.

- только `JiffyDOS_C64.bin` (8 КБ) → Jiffy-баннер, но штатная скорость IEC;
- `JiffyDOS_C64.bin` + `JiffyDOS_1541.bin` → JiffyDOS-скорость (если ROM
  совместим с 1541B и таймингом привода);
- любые другие ROM (custom KERNAL/BASIC/1541) — так же, через `F`.

## 6. Проверка

1. Собрать/залить `c64.kg`.
2. Создать `/c64/roms`, положить `JiffyDOS_C64.bin`/`JiffyDOS_1541.bin`.
3. OSD → System → C64 KERNAL → выбрать `JiffyDOS_C64.bin` (8 КБ). Ядро
   перезагрузится с новым ROM (ожидается баннер `JIFFYDOS V6.01`).
4. OSD → Drives → 1541 ROM → выбрать `JiffyDOS_1541.bin` (8 КБ,
   верхняя половина) или `JiffyDOS_1541-II.bin` (16 КБ, полный);
   проверить `LOAD"$",8`. Ядро само перезагрузится после загрузки ROM.
5. `Del` на пункте ROM → `default`, снова stock.
6. Без файлов и после `Eject` — заводской BASIC/KERNAL и 1541.

Тестовые файлы: `doc/artifacts/roms/`, а также
`../unoxt-c64-core-main/src/roms/JiffyDOS_Kernal.bin` (8192) и
`JiffyDOS_C1541.bin` (16384).

## 7. Ограничения

- CHARGEN (4 КБ) пока не загружается; BASIC/KERNAL и 1541 — да.
- Запись на диск в этом этапе не включена (только ROM-файлы).
- Второй дисковод — после замера ресурсов.
- Ресурсы: ROM-ы остаются в тех же BRAM (kernal/basic 4+4, 1541 8);
  добавляется только логика загрузчика.
