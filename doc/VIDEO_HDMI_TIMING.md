# HDMI/Video timing C64: свободная развёртка 720x576, контент 4:3

Дата: 2026-11-09. Сделано по мотивам SNES-ядра (`snes_video.v`), у которого
был тот же симптом на мониторе со скалером: «no signal», пока ядро в reset,
и плавающая длина кадра из-за привязки развёртки к строкам источника.

## 1. Что было

- `c64_video` сбрасывался сигналом `c64_reset`. Во время reset C64 / OSD
  Reset / автоперезагрузки после ROM счётчики стояли → **HSYNC/VSYNC
  пропадали** на 67 мс. Придирчивый скалер терял сигнал.
- Кадр генился «залипанием» на последней строке до прихода кадра VIC
  (до 40 строк) и ранним перезапуском кадра. Длина кадра плавала
  625..665 строк — скалер не держал лок.
- Активная область была 720x576 (5:4 квадратных пикселей), а панель 4:3;
  скалер показывал поле с чёрными полями.

## 2. Что стало

- Развёртка **свободная**, не зависит от VIC и от `c64_reset`:
  - ровно **625 строк** в кадре;
  - строка **870 или 871 такт clk_vid**, в среднем 870.39
    (7/18 строк длиннее на 1 такт);
  - HS 64 такта, начало на 732; VS 5 строк, начало на 581;
  - **стандартный кадр 720x576** (скалер принимает только его);
  - видимый экран C64 приводится к 4:3 **горизонтальным кропом**:
    `SRC_X0=36`, шаг 3/5 (720 выходных = 432 исходных), по вертикали
    показываются все 288 активных строк VIC;
  - кадр 625 x 870.39 = 543993 такта clk_vid — ровно кадр C64 PAL
    (312 строк x 504 `pixel_ce`), поэтому картинка не уплывает.
- Выход тактируется только `reset_host = ~locked` (power-on). OSD Reset,
  кнопка и автоперезагрузка ROM **не останавливают** HS/VS/DE.
- Если кадровый импульс VIC не приходит ~40 мс (C64 в reset, идёт загрузка
  ROM): картинка **чёрная**, но синхроимпульсы, DE и **OSD продолжают
  работать**.
- Первый кадровый импульс VIC выравнивает фазу; повторное выравнивание —
  только если фаза ушла больше чем на 10 строк (иначе картинка дёргалась
  каждый кадр).
- По вертикали показываются 270 исходных строк (`SRC_LINE0=21`,
  строки 21..290): лёгкий кроп верхнего/нижнего бордюра, экран C64 целиком.
- По горизонтали показываются 432 исходных пикселя (`SRC_X0=36`, шаг 3/5):
  боковой бордюр подрезан, видимый экран C64 320x200 ложится на 720x540
  как 4:3 (пиксель ~0.833, как у PAL).
- `src/rtl/c64video.v`: `locked`, `ev_timer`, дробная длина строки.
- `src/rtl/c64_machine.v`: `.reset(reset_host)` у `c64_video`.
- `src/rtl/c64_video.v`: `V_ACTIVE=540`, `SRC_LINE0=21`, `H_TOTAL=870`.

## 3. Параметры

```verilog
H_ACTIVE      = 720
H_TOTAL       = 870      // или 871; среднее 870 + 7/18
V_ACTIVE      = 576      // стандартный 576p (скалер принимает)
V_CONTENT     = 576      // полный кадр
V_OFFSET      = 0
V_TOTAL       = 625
H_SYNC_START  = 732      // 720 + 12
H_SYNC_END    = 796      // +64
V_SYNC_START  = 581
V_SYNC_END    = 586
SRC_LINE0     = 12       // все 288 активных строк VIC
SRC_X0        = 36       // 432 пикселя x 3/5 = 720 (4:3 по экрану)
```

Средняя длина строки: `870 + 7/18 = 870.3888`. Подобрано под
`clk_sys = 31.25 МГц`, `clk_vid = 27.027 МГц` и кадр C64 312x504.
Если менять PLL/clk_sys, пересчитать:
`H_avg = (312 * 504 / (clk_sys/4)) * clk_vid / 625`.

## 4. PLL 50.0 Гц (отложено)

Была попытка перевести PLL на задуманные в UCF 975 МГц
(`DIVCLK_DIVIDE=2`, `MULT=39`, `CLKOUT0=31`, `CLKOUT1=36`):
`clk_sys=31.4516`, `clk_vid=27.0833`, C64 и выход ровно 50.0 Гц,
строка 866/867. Но в сборке `FAST=1` не закрылся тайминг (setup −2.4 нс,
518 ошибок). Откатили на проверенные 31.25/27.027 (49.68 Гц).
Если скалеру принципиальны 50.000 Гц, нужно закрыть тайминг полной
сборкой (`-ol high`) или поправить критический путь; это отдельная задача.

## 5. Проверка на мониторе

1. Включить C64 — картинка должна появиться без «плавания» и без потери
   сигнала при OSD Reset.
2. OSD Reset (F12) — экран гаснет на ~67 мс, затем BASIC; OSD остаётся
   доступным.
3. Выбрать ROM — во время загрузки картинка чёрная, но OSD/синхронизация
   есть; после автоперезагрузки появляется новый ROM.
4. Активная область 720x540 (4:3); чёрная рамка вокруг синего экрана — это
   **бордюр C64** (его задаёт программа), а не потеря синхронизации.
   Для заполнения экрана самим экраном C64 нужен отдельный crop/zoom.
